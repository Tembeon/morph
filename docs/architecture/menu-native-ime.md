# P2: нативное меню и смена клавиатуры

2026-10-18, база `daa49e98`. Наблюдение на iPhone 16 Pro, iOS 27.0.1. Flutter-поведение этим этапом не меняется; P2 открыт.

В проверенной сцене `UIButton.menu` учитывает клавиатуру при открытии, а конечные координаты наблюдаемых строк не меняются после её появления или скрытия. Длинное меню может оставаться перекрытым клавиатурой.

## Сцена и результат

Публичный UIKit probe использует обычные UIWindow, UIViewController, UITextField и glass UIButton с showsMenuAsPrimaryAction. Кнопка занимает `(161,406,80,48)` в окне 402×874 pt. Через шесть секунд после menuActionTriggered поле получает или теряет first responder. Настройки телефона не меняются.

Сначала выполнены три контрольных режима с тремя строками. Затем те же режимы дважды повторены с десятью строками. Всего девять сцен в трёх успешных XCUITest прогонах. Для длинного меню наблюдаются строки 1, 2, 3 и 10; промежуточные строки не измерены.

| Длинное меню | До смены | После смены |
| --- | --- | --- |
| Клавиатура отсутствует | Первая строка y=410, десятая y=788…830 | Те же координаты |
| Клавиатура появляется | Первая строка y=410, десятая y=788…830 | Те же координаты, keyboard notification top=573 |
| Открытие при показанной клавиатуре, затем скрытие | Первая строка y≈135, десятая y=513…555 | Те же координаты |

В обоих длинных прогонах все четыре наблюдаемые строки и source имеют delta=0 по каждой координате. При изначально показанной клавиатуре первая строка выше контроля на 275 pt. При последующем показе клавиатуры низ десятой строки остаётся на 257 pt ниже её верхней границы. Снимок подтверждает перекрытие меню клавиатурой.

Публичная keyboard notification сообщает `(0,573,402,301)`, а XCUI keyboard element — `(0,590,402,226)`. Это разные границы; число 257 вычислено по notification. Display scale=3, safe area `(0,62,0,34)`, Dynamic Type L, Reduce Motion=false. Размеры сравниваются в points, без умножения на scale.

## Достоверность

Каждый snapshot хранит начало и конец последовательных XCUI запросов. Времена приложения и XCTest получены через CACurrentMediaTime на одном устройстве. Анализатор требует `before.end < keyboardCommandBegin` и `keyboardDid < after.start`, реальное изменение видимости клавиатуры и успешный responder command. В длинных прогонах запас до команды не меньше 3,33 с, после завершения перехода не меньше 0,84 с.

Отрицательный контроль подменяет before.end так, чтобы snapshot пересекал команду; анализатор отклоняет его с exit2. Независимый how-разбор повторил арифметику по исходным JSON. Сырые Xcode bundles/logs остаются локально; репозиторий хранит наши координаты, события, named screenshots и command receipts.

Это измерение конечных accessibility frames и отдельных снимков. Непрерывная траектория, оптический контур, закрытие/посадка, UIContextMenuInteraction с preview, другие окна/ориентации/клавиатуры и Flutter parity не проверены. По трём коротким строкам нельзя было бы доказать отсутствие avoidance: они и так помещались над клавиатурой.

## Следствие для P2

Не требуется вводить active keyboard retargeting только из предположения, что native menu обязано следовать за IME. Есть основание отделить выбор placement при открытии от последующей проверки source endpoint. Текущий prototype консервативно отзывает endpoint при изменении effective available rect; его показанный popup уже сохраняет прежнюю модель и placement.

Эти данные не определяют право landing. Selection/reopen и editor focus дополнительно проверены ниже; перед изменением консервативного detach нужны оптика возврата и проектирование границы placement snapshot и source validity. Hidden hold/reservation, реальное перемещение source и geometry loss остаются самостоятельными случаями. Контракт [viewport admission](menu-viewport.md) пока сохраняется.

## Selection, закрытие и повторное открытие после IME

После устранения блокировки XCTest выполнены два успешных прогона none/show/hide: ещё шесть сцен с десятью строками, двенадцать открытий и двенадцать selected callbacks. В каждой сцене Native first закрывает меню, та же кнопка открывает его снова, Native second тоже закрывает меню. Оба closed snapshots содержат отсутствующие наблюдаемые строки, hittable source и счётчики1/2. Один source token и frame `(161,406,80,48)` сохраняются.

| Режим | Первая строка после смены IME | После повторного открытия |
| --- | --- | --- |
| none | y410 | y410 |
| show | y410 | y≈135 |
| hide | y≈135 | y410 |

При повторном открытии placement учитывает текущее состояние клавиатуры; старое открытие сохраняет наблюдаемые координаты. Это поведенческое основание для разделения placement каждого открытия и source validity, а не доказательство внутренней архитектуры UIKit. В одном control reopen x меняется на⅓pt, поэтому полное равенство frames между открытиями не заявляется.

В обоих show-сценариях поле остаётся first responder на callbacks и reopen, затем получает `native` через XCTest без повторного тапа editor. Во время typeText приходят keyboard WillHide/DidHide при сохранённом first responder. У typed snapshot keyboardExists=true, но AX frame начинается наy891 вне окна874pt; снимок показывает скрытую клавиатуру. Получение ввода и focus здесь не означают постоянную видимость программной клавиатуры.

Analyzer проверяет интервалы перехода и двух выборов; подменённое время selected после closed.start отклонено с exit2. Независимый how-разбор пересчитал исходные JSON. [Результаты, receipts и снимки](../../tool/audit/foundation-p2-2026-10-18/native-ime-reopen/results.md). Первый неудачный запуск и подготовка стенда сохранены в отдельном историческом отчёте.

Функциональное закрытие и повторный tap не доказывают оптическую посадку или непрерывность траектории. Source не перемещалась; hidden hold/reservation и geometry loss остаются отдельными случаями. Консервативный Flutter detach этим этапом не меняется; следующий шаг — architect по placement snapshot/source validity с явным открытым optical gate.
