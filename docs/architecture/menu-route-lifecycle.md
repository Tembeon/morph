# P2: ранний route и готовность policy

2026-10-16, продолжение `d121d186`. Прототип в `example/lib/proto/`; это не выбор продуктового presenter и не завершение P2.

## Вызов приложения

```dart
ProbeMenuSource(
  pointerInput: true,
  menuBuilder: (_) => PopScope<void>(
    canPop: canDismiss,
    child: menu,
  ),
)
```

Дополнительных параметров подготовки или отдельной policy нет. Приложение использует обычные SDK scopes. `Navigator.pop` сохраняет безусловную семантику, `maybePop` проверяет policy уже открываемого меню. Проверка deprecated `WillPopScope` сохраняется как совместимость с async-границей SDK.

## Три границы

1. **Установка route.** Source Listener делает настоящий root push на down до того, как ancestor Navigator запишет этот pointer. Это сохраняет настоящий hold/move/up; поздний push уже опровергнут контрпримером отмены pointer.
2. **Измеренное открытие.** Модель начинает opening, после команды/advance route разрешает построить содержимое и получить фокус. Смена `_revealed` ещё не означает, что потомки существуют.
3. **Mount первого поддерева содержимого.** Приватный StatefulWidget строит builder и одним post-frame callback сообщает о готовности. К этому моменту обычные потомки зарегистрировали `PopScope`/`WillPopScope`. SDK modal scope сам по себе ещё не подтверждает mount содержимого.

Route хранит identity этого State, State хранит один флаг готовности. Ожидание первого mount принадлежит существующему `_DismissAttempt`, отменяется вместе с ним и не становится публичным Future. Detach проверяет точную identity; поздний post-frame callback не оживляет старый запрос. Неизвестные потомки, добавленные асинхронно позже, подчиняются обычной текущей SDK policy, а не обещанию заранее узнать все будущие scopes.

## Правило раннего закрытия

До измеренного открытия Back может отменить невидимую подготовку без создания содержимого. Несуществующая policy будущего builder не вызывается и не выдаётся за разрешившую отмену. После начала opening, в том числе до `_reveal`, модельный close всегда связан с policy. Command-mode `open()` уже раскрыт и тоже ждёт mount.

В запросе один раз фиксируется `consultPolicy`. Модельные запросы всегда получают true; SDK получает false только при невидимой ещё не открывшейся подготовке. Прежний pending identity, общий Future проверки и одноразовый допуск к pop сохраняются.

Если большой первый шаг проходит сразу deadline открытия и раннего close, admission отказывает в изменении движения до mount. Модель остаётся opening, после advance содержимое раскрывается и монтируется, затем читается настоящая policy. Разрешённое отложенное закрытие начинается из текущего состояния, отказ оставляет меню открытым. Готовый синхронный путь сохраняет измеренный deadline. Вызов приложения из интегрирования не добавляется.

Cover/uncover, replace/remove, programmatic pop, relinquish и Navigator disposal отменяют ожидающую операцию и разрешают оба её внутренних ожидания отказом. Готовность уже живого поддерева и одобрение отменённой операции — разные факты. После передачи успешного ответа SDK остаётся прежняя открытая граница атомарности до его commit.

## Отмена невидимой подготовки

`motion.close` уже очищает timeline и указатель модели. Подлинный move/up до disposal не должен возрождать меню; терминальный input после disposal тоже должен завершаться безопасно. Однако новый down через глобальный router мог повторно вооружить старую невидимую closing-модель, даже когда hit testing Navigator поглощал это нажатие. Провал воспроизведён.

Для невидимого closing route handler теперь не принимает новые команды модели и не захватывает новый pointer. Подлинный up/cancel отслеживаемого pointer очищает session identity. Это правило выведено из состояния route, отдельного флага нет. Reversal уже показанного closing-меню не блокируется. Поддельные binding events и отмена настоящего pointer не используются.

## Lifetime часов и фокуса

Ранний pop может финализировать ещё не смонтированный overlay прямо из кадрового callback. Прототип часов теперь прекращает публикацию/планирование, если `onFrame` освободил часы. Если disposal происходит из frame listener, ticker и timer освобождаются сразу, а notifier — после завершения текущего уведомления в finally. Формулы времени и порядок обычного advance не меняются.

При немедленном remove SDK продолжение `Route.didPush` ещё может прочитать `requestFocus`. Оно теперь false с начала disposal; последующее обращение SDK к отсоединённому Navigator не выполняется. Во время обычного живого route остаётся прежнее hidden/revealed поведение фокуса.

## Честная навигационная семантика

Ранний root route сразу становится current. Нижняя root page перестаёт быть current; локальная page во вложенном Navigator остаётся current в своём стеке. Root observers видят push и последующий pop даже при отменённом удержании с нулём запусков builder. `RouteObserver<ModalRoute>` сообщает covered/uncovered уже во время невидимой подготовки. Эти события не подделываются и не откладываются.

Проверка настоящего nested down/move/up подтверждает выбор root, сохранение pointer и контекст меню: его `ModalRoute`/`Navigator` — root popup/root Navigator, контекст source остаётся во вложенном Navigator. Стенд использует совпадающие полноэкранные координаты; преобразование смещённых и трансформированных источников этим не доказано.

Это цена раннего настоящего push, а не одобрение продуктового контракта. `requestFocus: false` сохраняет primary focus, но SDK исключает нижний root route из traversal, поскольку он уже не current. Escape из сохранённого nested focus, Router/BackButtonDispatcher, доступность и inherited context ещё требуют отдельных доказательств. Вызов nearest nested Navigator не перенаправляется автоматически в root.

Глобальный ввод под другим текущим route — отдельный обнаруженный риск. Исправление невидимого closing-состояния не решает взаимодействие уже показанного перекрытого меню или его удерживаемого pointer. Новая проверка currentness только на down также не была бы полной отменой текущего взаимодействия. Этот вопрос оставлен открытым.
