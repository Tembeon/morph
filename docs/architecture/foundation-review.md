# Основа morph: решение и обоснование

Статус: принятое направление архитектуры, 2026-10-15. Продуктовая реализация не начата; первый host-прототип P1 сравнивает два драйвера route, отчёт в `tool/audit/foundation-p1-2026-10-15/report.md`. Факты о коде относятся к `wip/measured-liquid-glass` на HEAD `78a22418`. Типы, примеры и список удаления находятся в `foundation-sketch.md`. Порядок работ находится в `docs/standalone-library-plan.md`.

## Проблема

morph становится библиотекой компонентов Liquid Glass с измеренным поведением iOS 27. Текущее дерево выросло из движка, который превращал любой виджет в overlay. Рядом с ним слой виджетов построил вторую среду выполнения. В итоге одна задача решается несколькими способами.

- Две системы представлений. Flight движка с shuttle OverlayEntry используют только меню, все через `MorphTargetSpec.vessel` (menu_host.dart:314, morph_context_menu.dart:843). Sheets, push zoom, alert и date picker являются routes слоя виджетов на `MorphMotionRouteMixin` и `MorphZoomSource`. Обе системы отдельно реализуют dissolve при потере источника (flight.dart:299 и zoom_source.dart:97), скрытие источника, crossfade реплики, радиус, перенос темы, scrim и протокол pop.
- Меню ведёт один прогресс двумя пружинами на двух часах (menu_host.dart:319-323, menu.dart:573-606).
- Пять реализаций пружины. Это `MorphSpring` с переходом в motor, `MorphSpringState`, `MorphChannel`, motor в flight и в нажатии контекстного меню (morph_context_menu.dart:393), `AnimationController` со `SpringSimulation` в navigation_stack.dart.
- Два критерия покоя. `reach` и `MorphRest` (d1f69935) используют lens, switch, flex и navigation. Старый `isAtRest(tolerance)` стоит в 70+ местах. Движения отвечают на запросы в двух диалектах.
- Около 23 собственных часов. Семь контролов работают на `MorphControlHost`, ещё около 16 State подмешивают `MorphClock` сами. Согласованность кадра между ними держат `MorphFrameSync` (live.dart:75, 48164486) и microtask в `MorphGlassHost` (glass_channel.dart:326).
- Четыре системы темы: `MorphTheme` движка как ThemeExtension из material_ui, `MorphWidgetsTheme` с импортом `package:flutter/material.dart` (d84e1253), `MorphGlassScope` и `MorphAdaptiveGlass`. Меню, sheet и scroll edge разрешают appearance вручную, мимо общего helper.
- Три политики выбора navigator. Sheet идёт через `morphPresentationNavigatorOf` (sheet.dart:199), alert и date picker через root navigator (alert.dart:368, date_picker.dart:607), push zoom через ближайший (navigation_stack.dart:1011).
- Больше 16 типов описания стеклянной поверхности. Контейнерный закон слияния существует в `LiquidField` на CPU и в `fused_law.glsl`, matte-путь использует другой blend `angularBlendRadius` из `gpu/sdf.glsl`, `gpu/material_sdf.glsl` и `analytic_geometry.glsl`, меню считает своё размытое объединение. Есть два tracer и шесть кешей shader (rendering.md, раздел inventory).
- Painter-шов возвращает Widget. Retention работает только для точного runtime type `MorphGlassRenderer`. Пользовательский painter перестраивает дерево каждый кадр.
- Около 245 публичных имён в четырёх точках входа: `widgets.dart` 120, `foundation.dart` около 60 вместе с четырьмя именами motor, `motion.dart` 54, `glass_painter.dart` 6. У `motion.dart` нет production-потребителя, его используют 28 тестов и один файл example.
- Зависимости `motor`, `flutter_shaders` (транзитивно тянет `package:flutter/material.dart`) и `equatable` (ноль импортов).

У routes слоя виджетов есть три реальные проблемы. Их `transitionDuration` равен нулю, поэтому `route.animation` сразу стоит около 1, пока движение виджета ещё идёт. Route становится непрозрачным с первого кадра и скрывает страницу под собой до конца zoom. `pushReplacement` освобождает заменённый route сразу, пока zoom ещё вылетает из него. Четвёртый пробел касается predictive back. Он есть только у legacy `MorphPageRoute` через собственный observer (route.dart:591), routes слоя виджетов его не реализуют.

Закрытие route при этом устроено правильно. `MorphMotionRouteMixin.didPop` вызывает `super.didPop` и затем `controller?.stop()` (motion_route.dart:42-48). Статус уже равен `reverse`, поэтому barrier перестаёт ловить нажатия, а фокус освобождается.

Решение обязано сохранить следующие ограничения.

- Измеренное движение является спецификацией. Время явное, события указателя получают метку своего времени через смещение между двумя часами ОС (FFI), кадры ложатся на сетку дисплея, часы спят в покое и дремлют до известного времени пробуждения.
- Инварианты стекла 1-13 из rendering.md. Backdrop в том же кадре, сборка один раз на структуру, сохранённые slots, ноль кадров в покое, никакого `OpacityLayer` между стеклом.
- Хвост меню играет источник. После первого пересечения нуля кнопка сама доигрывает undershoot и снова сливается с соседями в баре.
- В графе импортов morph нет Material, Cupertino и motor. Слоя совместимости нет. Оба рендерера остаются. Цель на Pixel 6a составляет 60 fps с запасом.

## Использование

Приложение ставит `MorphTheme` над root Navigator в обычном `WidgetsApp` и пользуется контролами. Scope, registry и controller не нужны. Пять сценариев с кодом находятся в `foundation-sketch.md`, раздел "Использование".

- Управляемый `MorphSwitch` с отказом. Родитель, который не перестроился с предложенным значением, отказал. Thumb возвращается от места, где его оставил жест.
- Sheet из кнопки с живым редактором во вложенном `MorphNavigationStack`. Источник называет `MorphSourceLink`, которым владеет State. Результат приходит через обычный `Navigator.pop`.
- Меню на кнопке бара. Меню является route на root navigator, кнопка доигрывает его посадку.
- Собственная стеклянная поверхность приложения и пользовательский painter, который рисует на Canvas и сохраняет retention.

## Форма

### Сначала данные

1. `MorphSpringState` описывает одну степень свободы. Пружина считается в замкнутой форме через SDK `SpringSimulation` от последнего retarget. Своё здесь только то, чего нет в SDK: огибающая `reach(t)` для видимого покоя и правило "не возвращаться раньше последнего изменения". Покой определяется одним правилом, `reach(t) < MorphRest.*`. Перенос всей модели между часами проверяется в P2 и сам по себе не требует `rebase(offset)` в каждой пружине.
2. `MorphMotion<E>` является единственным контрактом движения: `advance(t)`, `isSettled`, `wakeTime`, `settle()`, `drainEvents()`. Движение чистое и не хранит callback-полей. Предложение значения, haptic и выбор выходят как типизированные события `E`. Host раздаёт их и читает `widget.onX` в момент события.
3. `MorphMotionClock` является обычным объектом над `Ticker` от любого `TickerProvider`. Им пользуются и State контрола, и route с vsync от своего `NavigatorState`. Он владеет меткой времени событий, сеткой кадров, дрёмой и сном в покое.
4. `MorphHost` является кандидатом на общую базу State для анимированного виджета. Он объединяет часы, отслеживание нажатия, focus node, semantics, кеш сборки, сверку значения с родителем и раздачу событий. Общие механизмы нужны, обязательное наследование пока не принято: switch, меню и sheet должны подтвердить удобство формы до массового перевода State в единице 3. Если единая база требует лишних обязанностей или исключений, те же механизмы собираются композицией объектов и узких mixin. Route использует часы напрямую и не наследует State.
5. `MorphPresentationMotion` описывает движение одного семейства представлений. `MorphMotionRoute` является mixin на `ModalRoute`. Он владеет движением и часами и проецирует прогресс в SDK как `route.animation` через `MorphRouteAnimation`. Значение ограничено отрезком [0, 1], статус выводится из фазы движения. `didPush` возвращает `MorphSettleSignal`, future заглушённого Ticker, который завершается при покое. Поэтому `pushReplacement` держит заменённый route до посадки zoom.
6. `MorphSourceLink` является единственным знанием представления об источнике. Ссылкой владеет State, который представляет. Контрол с `source:` или обёртка `MorphSource(link:)` присоединяется к ней один раз, повторное присоединение проверяет assert. Ссылка отдаёт прямоугольник в пространстве overlay, форму, реплику, захваченные темы и видимость через opacity поверхности. После размонтирования источника она хранит последнюю геометрию.
7. Передача хвоста меню. При первом пересечении нуля route меню отдаёт всю модель кнопке и согласует её непрерывное время с часами нового владельца. Кнопка доигрывает undershoot. Повторное открытие во время закрытия продолжает движение от того владельца, который держит его сейчас. В каждый момент движение пишет ровно один владелец. Первый host-проход P2 подтверждает перенос через смещение времени; полная интеграция route ещё не проверена.
8. Одна функция размещения `morphPresentationNavigatorOf(context, level)`. Уровень является свойством семейства. Меню, контекстное меню, alert и popover date picker идут на root navigator, как в UIKit. Контекстные sheets идут на ближайший navigator вне собственного navigator стека.
9. Одна тема. `MorphTheme` является обычным `InheritedTheme`. `MorphThemeData` хранит brightness, tint, haptics, выбор рендерера и `appearances`, набор appearance по типу по образцу `ThemeData.extensions`. Один resolver разрешает appearance в порядке аргумент, тема, встроенная таблица. Таблицы объявлены один раз как `static const tables` рядом с классом appearance. Выбор рендерера является sealed-типом с тремя вариантами: адаптивный tier, фиксированный tier и пользовательский painter. Этот тип и типы painter-шва лежат в `lib/src/theme/`, сцена читает их оттуда, а тема не импортирует сцену.
10. Одна сцена. `MorphSurface` является единственным внутренним описанием поверхности, его напрямую читает vendored-рендерер. Поля поверхности имеют одного писателя. Контрол пишет геометрию и вид через `MorphSurfaceHandle`, представление пишет перенос и посадку через `MorphSurfaceCarry`. Слияние идёт через один конвейер поля и один tracer, два измеренных закона UIKit заданы данными `MorphFusionLaw` (сглаженное объединение контейнера и размытое объединение morph-контейнера для шейки меню). Один реестр shader владеет precache и прогревом. Painter-шов работает на Canvas (`backdropFilter` и `paint`), поэтому пользовательский painter сохраняет retention и backdrop того же кадра.

### Потоки

Контрол. `MorphPress` получает событие, host ставит метку `clock.stamp(event)` и передаёт её в движение. Сразу после команды ввода host забирает возникшие события через `drainEvents` и вызывает `onChanged` и haptics до возврата из обработчика ввода. На кадре часы кладут время на сетку, вызывают `advance`, доставляют возникшие при продвижении времени события и затем уведомляют `frames`. Очередь сохраняет порядок и не повторяет доставленные события; повторный вход из callback, закрытие и размонтирование проверяются отдельно. Сохранённые render objects и сцена читают движение без сборки. После кадра host сверяет значение с родителем. Родитель, который не перестроился, отказал. Типизированная очередь не переносит текущие синхронные callbacks на следующий vsync.

Представление. Функция показа выбирает navigator по уровню семейства, берёт `MorphSourceLink` и делает `push`. `install` создаёт часы, движение и `MorphRouteAnimation`. `didPush` запускает движение от метки события источника и возвращает `MorphSettleSignal`. `pop(result)` завершает future результатом сразу. `didPop` запускает закрытие, статус становится `reverse`, SDK перестаёт пропускать нажатия и освобождает фокус. В точке передачи меню отдаёт хвост источнику, остальные семейства доигрывают до покоя. Затем статус становится `dismissed`, и SDK завершает route.

Согласованность кадра между контролами решает прототип P3. Первый вариант оставляет часы на каждом host и добавляет одну упорядоченную фазу после всех ticker вместо `MorphFrameSync` и microtask в `MorphGlassHost`. Второй вариант заводит один Stage на `FlutterView` с фазами advance, publish и commit. Побеждает более дешёвый вариант из прошедших проверку.

### Что даёт SDK и что добавляет morph

| Задача | Механизм SDK | Собственное в morph и пробел SDK |
| --- | --- | --- |
| Жизненный цикл представления, back, Esc, barrier, фокус, semantics, veto | `ModalRoute`, `PopupRoute`, `PageRoute`, `PopScope`, `DismissIntent`, `NavigatorPopHandler` | Ничего. |
| Прогресс перехода для потребителей SDK | `AnimationController`, в том числе `unbounded` и `animateWith`, `TransitionRoute.createSimulation()` и `createAnimation()` | Кандидат `MorphRouteAnimation` проецирует движение с меткой времени события, сеткой кадров и дрёмой. Перелёт сам по себе не обосновывает отказ от SDK controller: P1 сравнивает варианты по этим требованиям и числу собственных обработчиков жизненного цикла. |
| Удержание заменённого route | Future из `didPush()` | `MorphSettleSignal`. Заглушённый Ticker не планирует кадров, `pushReplacement` ждёт `idle` (navigator.dart:4500 в SDK 3.47.2). |
| Predictive back | `PredictiveBackRoute` на route | Один observer на binding. Единственный диспетчер SDK живёт в Material (`predictive_back_page_transitions_builder.dart`). Свой observer уже есть в route.dart:591. |
| Темы в route | `InheritedTheme.capture` | Обновление при `didChangeDependencies` источника, `capture` не регистрирует зависимость. |
| Строки | `Localizations`, `LocalizationsDelegate` | `MorphLocalizations` с английскими строками по умолчанию. В `WidgetsLocalizations` нет подписи barrier. |
| Пружины | `SpringDescription`, `SpringSimulation` | `reach`, правило невозврата. Перенос времени всей модели проверяется отдельно в P2. Для `dampingRatio: 1` дискриминант равен ровно 0.0, SDK идёт по критической ветке. |
| Часы | `Ticker` | Метка времени, сетка, дрёма (clock.dart). |
| Стекло | `RenderObject`, `BackdropFilterLayer`, `ImageFilter.shader`, Flutter GPU | Сохранённая сцена и tiers по инвариантам rendering.md 1-13. |

### Глубина интерфейса

Публично остаются две библиотеки. `package:morph/morph.dart` экспортирует около 100 имён: компоненты, appearances, элементы меню, тему, стеклянный виджет, ссылку на источник и функции показа. `package:morph/glass_painter.dart` экспортирует пять имён painter-шва. Всего около 105 имён против примерно 245 сейчас.

Скрыто всё, что описывает механизм: движения, tunings, metrics, часы, host, модальные классы route, типы эпохи flights, настройки рендерера, GPU-типы и уровни размещения. Модальное представление вызывается одной функцией, меню является виджетом. `MorphNavigationStack` является единственным контейнером навигации, `MorphNavigationRoute` единственным типом страницы в нём, а `MorphNavigationPage` его формой для декларативного API Navigator. Replay-тесты импортируют `src/` напрямую. Ни одно публичное имя не называет этап представления, ticker, симуляцию или shader.

### Чего система не делает

- Не требует от приложения scope, registry или controller.
- Не вставляет представления в `Overlay` мимо route.
- Не публикует движения и tunings. Измеренная спецификация не является настройкой.
- Не импортирует Material и Cupertino. Brightness берётся из `MorphThemeData.brightness` или `MediaQuery.platformBrightnessOf`.
- Не владеет прокруткой. `Scrollable`, `ScrollPhysics` и физика large title остаются за Flutter.
- Пока не даёт приложению публичных морфов стекла и ядра анимаций. Их будущая форма опирается на те же внутренние типы: чистое движение с явным временем и поверхность, которую представление переносит через отдельный handle. Поэтому их публикация добавляет API, а не меняет фундамент.

## Решение по кандидатам

Происхождение. Одна модель независимо построила два кандидата. Свежий запуск той же модели в роли судьи сверил ключевые утверждения с кодом репозитория и исходниками Flutter 3.47.2 SDK и выставил оценки. Проверены строки SDK routes.dart:328, 1154, 2280, 654, navigator.dart:4500, путь критического затухания `SpringSimulation`. Строки репозитория взяты из трёх отчётов grounding, выборочно перепроверены motion_route.dart:42-48, route.dart:591, live.dart:75, glass_channel.dart:326 и curves.dart:11 в SDK. Тесты, сборки и прогоны на устройствах не запускались, предложенные типы не компилировались. Независимости разных семейств моделей здесь нет.

Основа взята от кандидата 1, ориентированного на механизмы SDK. Судья дал ему 25 баллов против 24. Оба кандидата сошлись в главном. Каждое представление, включая меню и контекстное меню, является `ModalRoute`. Пружина одна, правило покоя одно, движения выдают события вместо callback. Тема одна, внутреннее описание поверхности одно, публичных имён около 100.

От кандидата 1 взяты проекция `route.animation` через `MorphMotionRoute` и `MorphRouteAnimation`, `MorphSettleSignal`, передача хвоста меню, `MorphMotionClock` как объект, `MorphSpringState` через `SpringSimulation` с `reach` и `rebase`, observer predictive back, единый `MorphHost` и таблица SDK против собственного.

От кандидата 2 перенесены восемь частей.

1. Типизированный `MorphSourceLink` вместо тега `Object` и обхода элементов по правилу Hero.
2. Golden публичного API, который строится из модели элементов анализатора (`test/api/public_api.txt`), и `test/architecture_test.dart` с таблицей направлений импорта и allow-list SDK.
3. Первая единица миграции вырезает legacy-движок, мёртвый код рендеринга и флаги отклонённых экспериментов. Сначала вычитание, потом добавление.
4. Один писатель на поле поверхности через разделение `MorphSurfaceHandle` и `MorphSurfaceCarry`.
5. Один конвейер поля и один tracer, два закона слияния как данные. Копии blend `angularBlendRadius` в трёх файлах glsl и второй tracer `_OutlineTracer` удаляются после проверки паритета.
6. Один реестр shader вместо шести кешей.
7. Каталог на семейство контролов с файлами `<x>.dart`, `<x>_motion.dart` и `<x>_appearance.dart`.
8. Sealed `MorphGlassShape` и sealed выбор рендерера в теме.

Отложены до прототипа две части кандидата 2. Stage на каждый `FlutterView` проверяется в P3 против более простой упорядоченной фазы. Судья нашёл у Stage три риска: состояние в Expando переживает `testWidgets`, `TickerMode.getNotifier` устарел с 3.35, позиции из layout в transient-фазе отстают на кадр. Полная переделка vendored-слоя liquid в таблицу узлов тоже отложена. Основа делает меньший шаг. `RenderLiquidGlassLayer` уже собирает дочерние формы через `GeometryRenderLink` (liquid_glass_render_object.dart:869) и начинает читать `MorphSurface` напрямую.

Отклонено у кандидата 2 следующее. Публичный `MorphPresentationBoundary` добавляет настройку размещения, которая не нужна приложению. Route с `transitionDuration: zero` без переопределения `createAnimation` и `finishedWhenPopped` завершается сразу при pop. Публичный `inspector.dart` превращает отладку в контракт. У кандидата 1 отклонены тег `Object` с обходом элементов и обещание Hero без `HeroController`. Обещание Hero снято, потому что `WidgetsApp` не устанавливает `HeroController`.

## Принятые компромиссы

- Цена плавного `route.animation` пока не принята. Первый host-прототип P1 измерил в среднем 4,4 перестроения на кадр у отдельной проекции и 8,0 у SDK controller: работают SDK `ListenableBuilder` и barrier, содержимое строится один раз. Прежняя оценка около двух элементов не отражает полного объёма работы. Это сокращённый стенд открытия, а не продуктовый perf-сценарий или замер времени кадра. Потолки perf_counts не меняются; нужны продуктовые счётчики и Pixel 6a до выбора варианта.
- Дополнительный profile-прогон P1 на iPhone 16 Pro (120 Гц) подтвердил редактор с нативной клавиатурой, фокус/ввод и 16 циклов route. В сокращённой сцене total span p95 равен 2,383 мс у проекции и 2,170 мс у SDK controller, превышений 8,33 мс в измеренных интервалах нет. Это не измерение пропущенных кадров, энергии или продуктового стекла; отклонять SDK controller по одному числу перестроений оснований нет. Сырые данные и ограничения находятся в отчёте P1.
- Принимаем переопределение точек `TransitionRoute`: `createAnimation`, `createAnimationController`, `finishedWhenPopped` и обработчиков predictive back при прохождении P1. Уже в Flutter 3.47.2 `didAdd` (routes.dart:353) завершает только внутренний `_controller`, а `didReplace` (routes.dart:364) копирует значение только этого controller. Независимая проекция должна явно обработать оба пути. P1 проверяет начальные `Pages`, `Navigator.replace`, restoration, значение и статус проекции, непрозрачность overlay и завершение route. Это существующая обязанность адаптера; новые обращения SDK к `_controller` дополнительно ловят те же тесты.
- Принимаем ограничение `route.animation.value` отрезком [0, 1]. Собственное содержимое morph читает сырой прогресс с перелётом прямо из движения.
- Принимаем меню как route на root navigator. Программный push при открытом меню накроет меню. UIKit в этом случае тоже закрывает меню. Взамен остаётся одна система представлений.
- Принимаем, что `ThemeMode` Material-приложения не доходит до morph сам. Приложение передаёт `brightness` одной строкой в `builder`. Взамен в morph нет импортов Material.
- Принимаем потерю публичного `motion.dart`. Replay-тесты импортируют `src/`, потребители получают lint `implementation_imports`.
- Принимаем, что согласованность кадра до P3 остаётся на `MorphFrameSync` и microtask. Решение принимается по измерению, а не заранее.

## Рассмотренные альтернативы

- Вариант A прежнего разбора, общие внутренние helpers без объединения routes. Публичный контракт тот же, но меню остаются на flight, а routes на `MorphMotionRouteMixin`. Две системы представлений сохраняют повторённые dissolve, скрытие источника, перенос темы и протокол pop, и каждому новому семейству приходится выбирать систему.
- Ядро кандидата 2 как основа: Stage, таблица узлов сцены и session. Владение у него лучше, но основа зависит от переделки рендерера, которая не проверена на Pixel, и от контракта route, который кандидат не решил. Риск ложится под всю библиотеку, а не на её край.
- Меню как `OverlayPortal` или `OverlayEntry` с `LocalHistoryEntry`. Темы наследуются бесплатно, меню остаётся над routes. Но focus trap, Esc, semantics barrier, veto и блокировку нажатий при закрытии пришлось бы снова писать вручную, и navigator-правил стало бы два.
- Routes на `AnimationController` с измеренной `createSimulation()`. Кандидат с меньшим объёмом собственного кода, повторно сравнивается в P1. SDK поддерживает `AnimationController.unbounded` и произвольные симуляции, поэтому перелёт за границы не является причиной отказа. Нужно показать, сохраняет ли конкретная реализация старт от времени касания, сетку кадров, дрёму, прерывания и передачу хвоста меню. Итоговый отказ или выбор опирается на прототип и измерения.

- Painter-шов, возвращающий Widget. Painter может строить любое дерево, но retention есть только у встроенного рендерера, а пользовательский painter пересобирается каждый кадр. Canvas-шов даёт тот же retention пятью именами.

Первый проход времени P1 (отчёт `tool/audit/foundation-p1-2026-10-15/timing/report.md`) подтверждает паритет извлечённых часов с текущим `MorphClock` и возможность сетки/дрёмы у SDK controller. `stop()` отменяет push future и преждевременно освобождает заменяемый route; согласованное muting сохраняет future. Состояние паузы должно объединять ambient `TickerMode` и дрёму: прямое присваивание `muted` родитель может перезаписать. Поэтому временные требования сами по себе не исключают SDK controller. Итоговый адаптер должен иметь одного владельца времени; два проверенных прототипа часов нельзя просто запустить рядом для одного движения.

## Открытые вопросы и риски

1. Выдерживают ли меню как routes повторное открытие во время закрытия и стоимость первого кадра на Pixel 6a? Ответ даёт прототип P2.
2. Укладывается ли цена плавной анимации route в потолки perf_counts и в бюджет Pixel 6a? Первый host-стенд P1 показывает 4,4 перестроения на кадр у проекции и 8,0 у SDK controller при одной сборке содержимого; полного продуктового сценария и замеров устройства пока нет. P1 остаётся открытым.
3. Что дешевле обеспечивает согласованность кадра: Stage на `FlutterView` или часы на host с одной упорядоченной фазой после ticker? Ответ даёт прототип P3.
4. Остаётся ли перенос времени всей модели точным в настоящем route, если одни из часов в кадре передачи дремали? Первый host-проход P2 подтверждает спящий и дремлющий источник с привязкой к кадру при 1× и 5×; активный источник, порядок ticker и полный route replay ещё нужны.
5. Хватает ли Canvas-шва (`backdropFilter` и `paint`) для фирменного стекла с оптикой и свечением? В эскизе view не передаёт `style`, а Canvas заранее обрезан по контуру и исключает внешнее свечение. До удаления старого шва нужен пример с regular и clear рядом, движущимся фоном, слитой шейкой и внешним свечением. По результату решаются состав данных и отдельный внешний проход либо явно принимается ограничение возможностей painter. `abstract final` у трёх views также требует решения: scene не может реализовать такой тип из другой Dart-библиотеки. Выбор между `abstract interface` с возможностью внешней реализации и реализациями в той же библиотеке фиксируется до единицы 6.
6. Нужны ли в первом релизе страницы для go_router (`MorphSheetPage`), или достаточно `showMorphSheet` со страницы?
7. Подходит ли владельцу правило уровня окна для меню, alert и popover, или нужно прежнее правило самой внешней границы (97ef356b)?
8. Оправдана ли обязательная база `MorphHost` для всех анимированных State? До массового перевода нужны switch, меню и sheet с общими механизмами; вариант с композицией остаётся допустимым. Новый общий каркас принимается по потребностям этих виджетов.

## Замечания к исполнению, 2026-10-15

- Единица 2 выполняется последовательными проверяемыми изменениями: SDK-решатель, критерий покоя, advance-then-read, типизированные события, удаление motor. После каждого изменения проходят затронутые replay, чтобы причина расхождения оставалась локальной. Публичная совместимость со старым API для этого не нужна.
- Архитектурная проверка охватывает import и export во всём `lib/`, все условные ветви и достижимые сторонние runtime-зависимости, сохраняя оговорённую границу SDK. Golden API не заменяет эту проверку. Для чистых `*_motion.dart` действует отдельный запрет на импорт widget/host, включая собственное семейство. Отрицательные fixtures подтверждают, что запрещённый export, транзитивная зависимость и импорт host действительно обнаруживаются.

## Уточнение по первому проходу P2, 2026-10-16

33 новые host-проверки используют целую существующую `MorphMenuMotion` и сравнивают каждый кадр с непрерывно работающей моделью на 60/120 Гц. Передача сохраняет каноническое время модели, меняя только смещение к локальным часам владельца. Так вместе переносятся пружины, driven kicks, таймеры timeline, fusion и оставшийся хвост. Уникальный lease не позволяет callback старого route менять модель после повторного открытия. Повторное открытие проверено до передачи и после неё, пока источник ещё доигрывает посадку.

Это уточнение первоначального эскиза: одного `MorphSpringState.rebase` недостаточно для составного движения с отложенными событиями. У прототипа нет нужды перебазировать каждое поле модели. Отдельный метод не добавляется в ядро без потребителя; окончательная форма capture/resume определяется полной интеграцией P2.

На границе часов воспроизведены два неверных варианта. Простое `wake()` после сна теряет интервал до первого кадра нового ticker. Использование замершего `clock.time` дремлющего источника как якоря может, наоборот, перескочить вперёд при учёте времени дрёмы. Прототип привязывает передачу к текущему кадру и возвращает актуальный локальный якорь. Проверки проходят при 1× и 5×. Передача активному источнику в разных порядках ticker и согласованность кадра остаются задачами P2/P3.

Все 88 проверок прототипов и 117 существующих проверок меню, часов и routes зелёные; fixtures и допуски не менялись. Отчёт и хеши: `tool/audit/foundation-p2-2026-10-16/report.md`. Это проверка передачи модели, не готового menu route, пикселей бара или производительности устройства.

### Первый настоящий root route P2

Продолжение от 2026-10-16: `example/lib/proto/menu_route_probe.dart` использует `PopupRoute` на root Navigator, один экземпляр `MorphMenuMotion` и отдельные часы каждого владельца. Старые часы явно останавливаются при передаче. При первом закрывающем пересечении нуля source возобновляет модель с той же геометрией; SDK завершает route, пока источник ещё доигрывает хвост. Reopen до передачи забирает модель у закрывающегося route, после передачи — у источника. В обоих случаях прежний route перестаёт рисовать и писать модель.

15 сценариев проверяют вложенный Navigator, покадровый паритет движения, logical pop, reopen на 60/120 Гц, barrier с `PopScope`, освобождение ввода/фокуса, Escape, сохранение `EditableTextState`, удаление источника, принудительное удаление route и 20 циклов. При потере источника route сохраняет модель и закрывается до покоя, не обращаясь к State. Визуальный dissolve и перенос настоящего содержимого меню ещё не реализованы. Принудительное `removeRoute` в прототипе возвращает источник в покой без анимации; это отдельный путь SDK, а не измеренная посадка.

Часы уточнены до `resumeAt(absoluteStamp)`. Во время передачи на кадре используется его метка; при вводе между кадрами — текущее время engine clock. Последняя метка кадра после длительного простоя не является временем нового ввода. Три дополнительные проверки подтверждают абсолютное возобновление дрёмы между кадрами на 1×/5× и отмену отложенного wake при отдаче модели. Суммарно проходят 106 проверок прототипов и 117 существующих проверок, анализатор чистый. Отчёт: `tool/audit/foundation-p2-2026-10-16/route/report.md`.

Это ограниченный lifecycle-прототип с обычными заливками и фиксированной геометрией. Он пока открывает и закрывает модель явными командами; timestamp реального указателя, hold/drag, выбор строк, submenu/deferred content, контур группы бара и устройство ещё не проверены через этот route. Отдельная проекция используется для эксперимента и не объявляется победителем P1.

### Записанный ввод и контур P2

Следующий проход проверяет 10 записей iPhone на 60 и 120 Гц через настоящий `GestureBinding`: tap, hold, выбор строки, drag-select, раннее закрытие, повторные открытия и длинные протяжки flex. У flex используются исходные `delivered_t`; на 120 Гц дополнительно введено смещение часов указателя 37 с. На каждом наблюдаемом шаге маршрут сравнивается с непрерывной чистой моделью на тех же командах и временах. Выбор строк совпадает с записанными actions. Это паритет адаптера с существующей моделью, не новое измерение ошибки модели относительно всех нативных пикселей.

Поздний `Navigator.push` отменяет удерживаемый указатель через `_cancelActivePointers`, а binding удаляет его hit-test path и перестаёт доставлять последующие move/up. Игнорирование одного `PointerCancel` в pointer router не исправило бы потерю самого потока. В рабочем эксперименте source устанавливает скрытый route на pointer-down из собственного Listener, до того как ancestor Navigator зарегистрирует этот down. Содержимое строится и фокус запрашивается только при измеренном открытии; pending barrier включается при ожидающем tap-open. Настоящая отмена до hold удаляет скрытый route. 20 replay и проверки фокуса/отмены проходят. Это уточнение времени установки route; `NavigatorObserver` и `ModalRoute.isCurrent` видят раннее добавление, его влияние ещё проверяется до принятия продуктовой формы.

Два оставшихся пробела подтверждены контрпримерами. Pointer-путь вызывает закрытие из timeline движения и затем программный `Navigator.pop`, который обходит `PopScope`. Прежняя проверка SDK barrier/veto относится к командному режиму стенда и не закрывает этот случай. Нужен запрос закрытия до изменения фазы: host согласует его с SDK и только после разрешения посылает движению команду с исходным временем. Форма события уточняется в P2 и входит в контракт единицы 2.4.

Второй пробел находится в отрисовке. При первом пересечении нуля в изолированной сцене fusion radius ещё равен 2,031 pt. Немедленная замена Gaussian-контура меню контейнерным законом бара меняет 981, 1086 или 1382 пикселя при масштабе 3× для зазоров 12, 8 и 0 pt. Сохранение перенесённого контура даёт нулевую разницу при смене владельца. Успешная передача `RRect` не доказывает непрерывность поля; source должен использовать перенесённый контур/закон. Это сравнение двух путей нашего renderer на одном кадре, не native parity и не полный golden настоящего бара.

Суммарно проходят 135 проверки прототипов, включая новые отрицательные проверки позднего push, veto и трёх контуров. Они воспроизводят отвергнутые варианты и не ослабляют критерий P2. Отчёт, отклонённая проверка pixel-zero и собственные PNG: `tool/audit/foundation-p2-2026-10-16/input/report.md`. Продуктовые файлы и измеренные константы не менялись.
