# morph pre-release audit - 2026-10-03

Read-only static audit of branch wip/measured-liquid-glass at 9d1a0d3 plus
the uncommitted working tree (disabled-state porting in progress in many
widget files; findings in those files describe the tree as read on
2026-10-03 and may shift). No code was changed. `flutter analyze` is
clean (0 issues). Items marked (?) were inferred by reading, not run.

Severity: P0 ships broken / crash / silent wrong behaviour in release for
the common path; P1 real bug or contract violation a consumer will hit;
P2 debt or inconsistency to fix before a release; P3 nit.
Size: S under half a day, M about a day, L several days.

## Summary

- No P0. The architecture holds where it matters: the engine imports
  nothing from widgets or glass; ONE geometry, ONE rect resolution, ONE
  keyboard math, ONE content chain, ONE drag composition and the
  frameTicks merge are all intact; no `dynamic` except SDK override
  signatures; no non-ASCII and no TODO/FIXME in morph-authored code; no
  cascades in the widget layer; tickers sleep on settle.
- About 25 P1s, clustered in four places: (1) route lifecycle (a
  MorphPageRoute removed without a pop leaks a hidden source and an
  invisible flight; alert/sheet/edge swipe pop the TOP route, not their
  own; Esc dead on sheets, Android back skips the alert cancel handler);
  (2) bars (duplicate ValueKey when an id returns while still fading out;
  the navigation config signature ignores callbacks so the shared bar
  fires stale closures); (3) controls (no pointer-id gating in five hosts,
  the small lens RESTARTS on re-lift against the exemption rule,
  programmatic value jumps feed the flex loop a fake acceleration, the
  controls diverge from props when a parent rejects onChanged); (4) glass
  (the liquid tier never checks at runtime that Flutter GPU is there and
  silently draws fake glass; no BackdropGroup installed by the package,
  so every surface of a consumer app pays a full-screen readback).
- The known silent failure (sheet zoom with a mis-scoped `from:`) is NOT
  fixed: `MorphScopeState.tagOf` is still assert + `!`, so release now
  dies with a bare "Null check operator" instead of the assert message.
  The same assert-then-`!` pattern is in eleven more entry points (list
  in section 2).
- Debt: four hand-rolled copies of the motion-finalized route pattern
  and the zoom-source plumbing, two menu hosts, fifteen copies of style
  resolution, seven copies of the control host boilerplate, about 2,000
  lines of dead upstream renderer code still compiled into every app,
  bare measured literals in tab bar / switch / alert / bar hosts.
- Docs: one real passport-vs-code number mismatch (lens travel spring),
  README stale (pins v0.1.0, says glass is "up to the app", no Apache-2.0
  notice for the vendored renderer), CLAUDE.md has two stale claims.

## 1. P1 findings

### Engine (lib/src)

E1. P1 S - route.dart:336-341 (dispose), no didComplete/didRemove handling.
A MorphPageRoute removed without a pop (removeRoute, pushReplacement or
pushAndRemoveUntil over it, go_router `go`) never runs didPop: the flight
stays settled with `routeOwnsContent` true, content shows nowhere, the
source tag stays hidden forever. Fix: in dispose, if the flight is not
finished, flip routeOwnsContent false and `close()` when the tag is
mounted, else `abort()`. Test: removeRoute while settled.

E2. P1 S - route.dart:58 `MaterialLocalizations.of(context)` throws under
a WidgetsApp/CupertinoApp; the shuttle already uses the tolerant
`Localizations.of<MaterialLocalizations>` (flight.dart:955) and CLAUDE.md
says MaterialLocalizations is no longer required. Fix: same tolerant
lookup.

E3. P1 S - flight.dart:304-316 (`_pushHistoryEntry` onRemove ->
requestDismiss). When a declarative owner (MorphAnchor) declines the
dismissal, the LocalHistoryEntry is already consumed; the next Esc/back
pops the page UNDER the still-open overlay. Fix: after requestDismiss, if
still `isOpenOrOpening`, restore the entry (post-frame). Add a test.

### Bars and navigation

B1. P1 S - bar_motion.dart:315-327 (`_item`/`_capsule` skip leaving
entries) with bar_items.dart:1079 (`ValueKey<Object>(button.id)`). An id
that comes back while its old item is still fading out (push-pop-push
within ~0.4 s, the `morph.back` id, toolbar flip-flop) gets a twin; both
are built in one Stack with the same key: "Duplicate keys" in debug,
undefined in release. Verified by reading. Fix: in setLayout revive the
leaving entry (clear `leaving`, bump generation, retarget presence to 1
and frame to the new rect). Add a test.

B2. P1 M - navigation_stack.dart:69-97, 172-178. The
MorphNavigationConfig signature omits callbacks, menu rows and non-Icon
icon widgets, and compares ids by `toString()` (1 == '1'). A config
whose only change is a new onPressed closure never refreshes: the
shared bar fires the OLD closure with stale captured state. Fix: value
equality incl. callback identity (add `==` on MorphBarButton/Group in
bar_items.dart); the Navigator widget is built once, so the old publish
loop cannot recur - pin with a test.

B3. P1 S - bar_items.dart:729-737 layout signature `.join('|')` of ids:
same toString collision; a layout whose ids change but rects do not is
not applied. Fix: element-wise compare.

B4. P1 S - navigation_stack.dart:639-641 edge swipe commit does
`route.navigator?.pop()`: pops whatever is on top, a route pushed during
the swipe is popped instead. Fix: `isCurrent ? pop() : removeRoute(route)`.

B5. P1 S - navigation_stack.dart:586-589, 670-691. `_EdgePop.dispose`
mid-drag (or a route disposed while its controller animates) never calls
`didStopUserGesture()` / `_swipeEnded`: `userGestureInProgress` stays true
and the bar drift stays on. Fix: stop and remove listeners in dispose.

B6. P1 S - navigation_stack.dart:265-267 back menu `popUntil(route ==
target)` with `pages` captured at build; a target removed meanwhile pops
to empty. Guard with `target.isActive`.

### Menus

M1. P1 S/M - menu.dart:674-675 and bar_items.dart:985-986. Without an
ambient MorphScope, MorphMenuButton wraps itself in a private scope;
removing the button disposes that scope, which aborts the flight: the
menu vanishes instead of the documented dissolve (menu.dart:185). Fix:
document/assert an ambient scope as required or hoist the private scope
above the overlay.

M2. P1 M - menu.dart:372-385, bar_items.dart:588-599. After the host
State is disposed, MorphMenuLayer keeps reading a motion that no longer
advances while the engine closes/dissolves (frozen menu); `_BarMenu.repaint`
is never disposed (leak). Fix: on dispose snap the motion to closed and
draw from the flight value; dispose repaint on `flight.closed`.

M3. P1 M - menu_motion.dart:1057-1083, 1130-1146. Menu height is never
capped: rows past the safe area are unreachable and there is no
scrolling (UIKit scrolls). Fix: cap to the safe area and scroll the rows
(measure UIKit's scroll first).

M4. P1 S - menu.dart:396-400, morph_context_menu.dart:674: an `overlay:`
that is not an ancestor yields garbage geometry in release (only a debug
assert inside getTransformTo). Fix: verify ancestry once and throw
FlutterError (shared helper with engine `morphAnchorRect`).

### Sheets, zoom, alerts

S1. P1 S - sheet.dart:181-182 `barrierDismissible => false` disables
ModalRoute's dismiss action: Esc does nothing on a dismissible sheet.
Fix: `=> dismissible` (safe: buildModalBarrier is an IgnorePointer).

S2. P1 S - alert.dart:326-352. Android back / `Navigator.pop()` leaves
`_chosen` null, so the cancel action's onPressed never runs (Esc and
tap-outside do run it). Fix: in didPop map a null result to the cancel
action.

S3. P1 S - alert.dart:487, 497 and sheet.dart:426, 461 call
`Navigator.of(context).pop`/`maybePop`: they pop whatever is on top; a
route pushed from a handler above the alert/sheet is popped instead.
Fix: `isCurrent` guard or `removeRoute(this)`.

### Controls

C1. P1 S - small_lens.dart:115-119. `lift()` calls
`setState(t, value, liftVelocity)` on progress and size: a touch during
the landing overwrites the current velocity with +18/s - a RESTART,
which the native-fidelity exemption forbids ("retargets from its current
(value, velocity), never restarted"). Verified by reading. Fix: inject
liftVelocity only from rest (or add it); record a re-lift-mid-landing
case to settle the law.

C2. P1 S - slider_motion.dart:338 `setValue` + small_lens.dart:156-161.
A programmatic jump (keyboard step, a11y adjust, parent value change) is
seen by the flex integrator as acceleration: a 26 px step gives a stretch
target near 2.7 and `scaleY = 2 - stretch` below 0. Fix:
`MorphSmallLens.resetFlex(position)` called from setValue; clamp scaleY
positive. Check switch_motion for the same path.

C3. P1 S - lens_motion.dart:316-323 `slots` setter snaps travel/width but
not `_flex`/`_previousVisible`: a relayout during a lift (rotation, text
scale) becomes a drift/scale kick. Also `_tanh` (lens_motion.dart:633)
uses exp(2x) -> inf/inf = NaN for x > ~355. Fix: reset flex in the
setter; saturating tanh.

C4. P1 M - switch_motion.dart:190, lens_motion.dart:621,
slider_motion.dart:398. The motion commits before the parent confirms;
a parent that rejects onChanged (confirm dialog) never rebuilds and the
control shows the rejected state. Fix: post-frame reconcile
`widget.value != motion.value -> motion.setValue` in each host.

C5. P1 M - segmented_control.dart:341, tab_bar.dart:374-395,
switch.dart:238-250, slider.dart:186-219, glass_button.dart:402-424,
lens_driver.dart:25-43: no pointer-id gate. A second finger re-runs
pointerDown and replaces the first finger's state; the first finger's
up commits with the wrong state. stepper, page_control and the date
label already gate. Fix: one `_pointer` gate in the shared host (WP-H).

C6. P1 S - date_picker.dart:417-436, 460. The compact label uses a raw
Listener, not MorphTouchListener: inside a list a scrolling swipe dims
the label and opens the overlay if the finger lifts inside it. Same
family: search_field.dart:345-354 lifts the capsule under a scroll (?).
Fix: MorphTouchListener (`delaysInScrollable`, `onPointerLost`).

C7. P1 S - segmented_control.dart:184-193. Growing `segments` with a new
`selected` at or past the old count skips the select; `_sync` only
replaces slots, so the lens stays on the old index forever. Fix:
reconcile selection after the slot update.

C8. P1 S - tab_bar.dart:253-274, segmented_control.dart:239-245,
page_control.dart:449. Empty items/segments throw RangeError in
MorphLensMotion; out-of-range `selected` throws; page control `count: 0`
plus an arrow key throws in `clamp(0, -1)` and announces "page 1 of 0";
segmented accepts an infinite maxWidth. Fix: constructor asserts plus
release-safe clamping.

### Glass

G1. P1 M - glass_liquid_native.dart:14, glass_renderer.dart:117-126.
`liquidAvailable` is compile-time only (`dart.library.io`). On Android
without Impeller/Flutter GPU, or an app missing the
FLTEnableFlutterGPU / EnableFlutterGPU flag, the tier, `tierOf` and the
governor all say liquid while the layer silently draws FakeGlass
(liquid_glass_layer.dart:296-321, debugPrint in debug only). Fix:
`precache()` resolves a runtime flag (gpu context + bundle load) and
caps the best tier at frosted; document the Info.plist / manifest flag
on MorphGlassRenderer.

G2. P1 S - flutter_gpu_geometry_renderer_native.dart:108-117. A failed
GPU bundle load is evicted from the cache and retried by every new layer
(each lift creates one). Fix: sticky negative cache shared with G1.

G3. P1 S - glass_tier.dart:280-285, glass_liquid_native.dart:170. The
package never installs a BackdropGroup; with no ancestor group every
LiquidGlassLayer wraps its own, so each control pays a full-screen
readback. Only the gallery adds one (example gallery.dart:75); no
dartdoc tells consumers. Fix: wrap the child in BackdropGroup inside
MorphAdaptiveGlass, or document it on MorphGlassRenderer/MorphGlass.

G4. P1 S - glass_renderer.dart:504, 548; glass_liquid_native.dart:379.
Frosted BackdropFilters pass no `backdropGroupKey`: each surface reads
back the full screen on its own (matches the spec's "frosted not cheaper
than liquid on controls"). Fix: `backdropGroupKey:
BackdropGroup.of(context)?.backdropKey`.

G5. P1 S - glass_tier.dart:109-130, 194-216. The governor has no warm-up:
startup jank (shader warm-up, first route) in the first 30-frame window
steps liquid down and records a failure that doubles later waits. Fix:
`warmUp` on the policy (ignore the first second after mount / tier
change).

G6. P1 M (?) - pubspec.yaml `assets: - build/shaderbundles/` with
hook/build.dart:6-15 and renderer/shaders.dart:27. A build OUTPUT is
declared as an asset; for a git consumer the hook writes into the pub
cache. A clean consumer may fail with a missing asset directory if
assets resolve before the hook; with data assets on, the 403 KB bundle
may ship twice; the hook has no target check (bundle ships to web) and
no error handling (a missing impellerc fails the consumer's whole
build). Fix: verify with a consumer app on a clean pub cache, then pick
one asset mode, skip web, and catch failures so G1 falls back to frosted.

G7. P1 L - glass_liquid_native.dart:330-341, 463-550. `_Magnified`
mounts the full `content` once per overlapping slot times three strips
plus the original: up to ~7 content subtrees built and laid out every
frame while a lens is lifted. A GlobalKey or FocusNode in consumer
content (a tab icon) crashes or double-attaches. Fix: paint the copy
from one layer/picture with per-strip clip and transform; meanwhile
assert/document "no GlobalKeys in content".

### API

P1api. P2 S - flight.dart:487-505 public `MorphFlight.launch` exposes
`routeMode:`; a consumer passing true gets a flight with no history
entry that never hands over. Make launch @internal or hide routeMode.

P2api. P2 S - Mutable public state: `MorphFlight.sourceRect` /
`lastTargetRect` (flight.dart:187, 190) documented read-only but
writable; `MorphScopeState.lastFlight` is a writable ValueNotifier
(expose ValueListenable; it also retains the last finished flight);
`MorphFlight.controller` lets consumers bypass entry/history (document
scrub-only).

P3api. P2 M - Breaking hazard: `MorphSheetRoute.source` and
`MorphNavigationRoute.zoomSource` take an engine `MorphTagState` that a
consumer cannot obtain (`tagOf` is @internal); MorphNavigationRoute
publicly exposes zoomFrom/zoomPop/zoomClosed/attachZoomView/zoomIsCurrent
through an @internal interface. Take an id and resolve inside; hide the
plumbing. Do it before tagging.

P4api. P2 M - Motion classes exported publicly with mutable fields
(MorphSwitchMotion, MorphSliderMotion, MorphSmallLens, MorphLensMotion,
MorphGlassButtonMotion, MorphPageControlMotion, MorphProgressMotion,
MorphDatePickerMotion, MorphSearchMotion, MorphTouchGlowMotion): freezes
